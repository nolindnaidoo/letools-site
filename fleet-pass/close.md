# Step 8: Close

Prove the branch is whole, open the pull request, and write the ledger row. A
pass that is not closed did not happen.

<!-- read-rule:start -->
> **Read rule.** Every file in this document's scope is opened and read from
> its first line to its last, during this pass, before any check below is
> answered. Nothing is answered from memory of this repo, from a sibling repo,
> from an earlier pass, from a summary, or from a comment, a test name, a
> README or an `AGENTS.md`. A search result locates code. It never replaces
> reading the file it points into. A check on a file that was not read in full
> during this pass is `not done`, never `pass`. Where the code and a run cannot
> settle a question, the answer is `unknown` plus what is needed to settle it.
> No guesses.
<!-- read-rule:end -->

## Scope

Read in full: the complete diff of the branch against `main`
(`git diff main...HEAD`), the pass record, and every document the diff should
have updated: `CHANGELOG.md`, `AGENTS.md`, `README.md` and their `crate/`
counterparts.

## Checks

**CLOSE-1. The record is complete.** Every check in every step has an answer.
There is no `not done` and no blank row. Each `unknown` is listed in the pull
request as an open question for the owner, with what would settle it.

**CLOSE-2. Every finding is closed or carried.** Each one is either fixed, with
its commit and test named, or carried, with the reason and the owner's decision
needed. Nothing is dropped.

**CLOSE-3. Every new test was seen to fail.** For each fix, the record holds
the failing output from running the test with the fix stashed.

**CLOSE-4. Every gate from BASE-4 is run again, once, on the final commit.**
Same list, same commands, results recorded beside the baseline. Anything red
that was green at baseline is a regression the pass introduced and blocks the
pull request.

**CLOSE-5. The cross-repo gates pass.** From a checkout of `letools-site` with
the tool repos beside it:

```bash
bun run check:fleet ../
bun run check:locales ../
bun run check:doc-paths ../
bun run check:registry
```

A `check:fleet` failure means a shared file was changed in this repo and not
copied to the rest.

**CLOSE-6. The repo's documents match its code.** Each behaviour change has a
CHANGELOG line. Each defect that was fixed and could recur has an entry under
the repo's invariants, naming the test that holds it. Generated README sections
are regenerated by their scripts, not edited.

**CLOSE-7. The diff holds only the pass.** Read the full diff. No unrelated
refactor, no formatting churn, no leftover probe test, debug output or scratch
file. Every commit has the noreply author address and a conventional subject:

```bash
git log main..HEAD --format='%ae %s'
bun run lint:commits
```

**CLOSE-8. The pull request is opened, and nothing further.** Push the branch
and open one pull request against `main`. Its body is the findings table from
the record: id, step, what was wrong, the commit, the test. It lists the open
`unknown` items and anything carried. It carries no AI attribution.

The pass stops here. Merging, version bumps, tags and publishing are not part
of it.

**CLOSE-9. CI on the pull request is read.** The other operating systems and
any gate marked `not run here` at baseline run there. Record the result of each
job. A red job is handled before the row is written.

**CLOSE-10. The ledger row is written.** In `fleet-pass/LEDGER.md`: the
baseline commit, the record, the pull request, the date and the counts. The
record is committed to `letools-site` in the same change.

**CLOSE-11. New defect classes are added to these documents.** For each
finding that no existing check would have led to, add a check to the matching
document in that same `letools-site` change, so the next repo is examined for
it. Add nothing that names a tool repo.

## Done when

The pull request is open with green CI or a recorded reason for each red job,
and the ledger row and record are committed.
